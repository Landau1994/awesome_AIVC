# BixBench: a Comprehensive Benchmark for LLM-based Agents in Computational Biology

## Quick Summary
BixBench is a specialized benchmark designed to evaluate the ability of Large Language Model (LLM) agents to perform end-to-end bioinformatics data analysis. It comprises 61 real-world analytical scenarios ("capsules") with over 200 associated open-answer questions that require agents to explore biological datasets, execute multi-step code trajectories in a Jupyter environment, and interpret results. The study reveals that current frontier models (GPT-4o and Claude 3.5 Sonnet) perform poorly, achieving only ~21% accuracy in open-answer formats, which underscores a significant gap between current AI capabilities and the requirements for autonomous scientific discovery in computational biology.

## Key Points
- **Practical Focus**: Shifts evaluation from rote knowledge recall to practical, multi-step analytical trajectories in bioinformatics.
- **Complexity**: Scenarios involve heterogeneous data files (CSV, RDS, etc.) and require proficiency in Python, R, and Bash.
- **Benchmark Scale**: Includes 61 scenarios and 205 expert-curated questions.
- **Performance Gap**: Even the best frontier models struggle, often performing near random in multiple-choice settings when tasked with interpreting their own analyses.
- **Open Framework**: The authors open-source both the dataset and a custom agent framework built on "Aviary" with a pre-configured Docker environment.

## Methods
### Data
- **Analysis Capsules**: Expert bioinformaticians (PhD level) assembled code notebooks, input data, and metadata (hypotheses, results) from 61 real-world research scenarios.
- **Question Generation**: Initial MCQ drafts were generated by an LLM (Claude 3.5 Sonnet) and subsequently reviewed/edited by human experts to ensure accuracy and relevance.
- **Categories**: Covers a wide range of fields including Genomics, Transcriptomics, Differential Expression Analysis, RNA-seq, and Phylogenetics.

### Model Architecture
- **Frontier Models**: Primary evaluation conducted on **GPT-4o** and **Claude 3.5 Sonnet**.
- **Agent Framework**: Built using **Aviary**, an extensible gymnasium for language agents.
- **Environment**: A Docker container (`BixBench-env:v1.0`) pre-loaded with standard bioinformatics packages (Python, R, and Bash).

### Training/Evaluation Strategy
- **Agentic Execution**: Agents are provided with an empty notebook and tools: `edit_cell` (modify Jupyter cells), `list_workdir` (inspect files), and `submit_answer` (finalize answers).
- **Open-answer Regime**: Agent responses are compared to ground-truth answers using an LLM-as-a-judge (Claude 3.5 Sonnet).
- **Multiple-choice Regime**: Used as a proxy to evaluate performance with/without a "refusal" option, employing majority voting over five parallel runs.
- **Ablations**: Tested the impact of image/plot generation and the presence of an "insufficient information" refusal option.

## Results
| Metric | Claude 3.5 Sonnet | GPT-4o | Baseline (Recall) |
|--------|-------|----------| --- |
| **Open-answer Accuracy** | ~21% | ~15% | ~25% (Recall) |
| **MCQ (with refusal)** | ~25% | ~21% | ~20% (Random) |
| **MCQ (without refusal)** | ~40% | ~33% | ~25% (Random) |

*Note: The "Baseline" refers to the model's ability to answer questions from internal knowledge without access to the provided analysis notebook.*

## Critical Analysis
### Strengths
- **Authenticity**: Tasks are based on real-world research trajectories rather than synthetic puzzles.
- **Reproducibility**: Use of Docker containers ensures consistent software environments for evaluating agents.
- **Rigorous Evaluation**: The inclusion of both open-answer and MCQ (with/without refusal) provides a nuanced view of agent failures.

### Weaknesses
- **Judge Dependency**: Evaluation of open-ended answers relies on another LLM, which may have its own biases or limitations in scientific reasoning.
- **Model Selection**: Only two frontier model families were extensively tested; open-source reasoning models (e.g., DeepSeek R1) were noted to struggle in preliminary tests but weren't fully benchmarked.
- **Saturation Risk**: As models improve, the benchmark might require more "distractor" files or even more complex multi-omic integration tasks to remain challenging.

### Questions
- How would models specifically optimized for code (like DeepSeek-Coder) perform in this agentic framework?
- To what extent does the "LLM-as-a-judge" agree with human experts on the correctness of the 21% of "correct" open-answers?

## Notes
- The models actually performed *worse* as agents than they did on pure recall, suggesting that the complexity of the task (or the noise introduced during analysis) currently hinders rather than helps frontier models.
- "Majority voting" helps MCQ performance but does not significantly close the gap to human expert performance.---
